Ongelma ja tavoite

  • A, optimi: agentti tutkii itse valitsemiaan kohteita, käytännössä hakukoneesta alkaen: hae, avaa tulokset, lue, vastaa lähteineen.
  • B, kapeampi: agentti lukee annetun sivun, esim. "hae lokakuun tarjoukset kaalimato.com".
  • Agentti ajaa muualla (esim. jonkun muun kubessa): selain tarjotaan verkon yli, ei Macin docker execillä.
  • Vaatimukset:
    • oikea headful Chromium, ei headless-skriptiä
    • jokaisella selaimella oma julkinen IP valitusta exitistä
    • ei vuotoja: ei suoraa ulosmenoa, ei DNS:ää, ei IPv6:ta tunnelin ohi
    • ihminen voi katsoa ja ottaa ohjat
    • minimaalinen: kontteja ja env-muuttujia, kube vain yksi ajotapa

Live: kaksi selainta, kaksi maata, sama tehtäväPanel n100-1:llä, tehtävä B ajossa rinnakkain Cape Townin ja Kulloon kautta

Arkkitehtuuri

hydra-browser: yksi imagedocker run sellaisenaan, podina sellaisenaan

  • Debian trixie + Chromium 154, headful Xvfb:ssä, AutomationControlled pois, oma profiili.
  • Ohjaus: Playwright MCP Streamable HTTP:nä :8931/mcp, kiinni Chromiumissa CDP:llä. CDP vain 127.0.0.1:ssä.
  • Ihminen: noVNC :6080 (Node-silta x11vnc:hen, ei Pythonia).
  • Status :8080: ready, exit, egress (ipinfo tunnelin läpi), iso IP-sivu.
  • Selain ajaa käyttäjänä hydra ilman capabilityjä: murrettu sivu ei voi koskea palomuuriin.
  • Evästebannerit pois: "I still don't care about cookies" 1.1.9, SHA-256-tarkistettu.
  • Kieli ja aikavyöhyke exitin mukaan (LANG, TZ).
IP-sivu kortin live-näkymässä: IP, paikka, WebRTC (STUN), DNS-resolveri, sormenjälkirivit.

Ulosmeno ja killswitch

  • Kaikki podin kontit jakavat netnsin: Chromium, WebRTC, DNS, kaikki samojen sääntöjen alla.
  • Killswitch ensin, tunneli vasta sitten: iptables INPUT/OUTPUT/FORWARD DROP.
  • Ulos vain: wg0, salattu UDP exitille, vastaukset klusterin asiakkaille.
  • DNS vain tunnelin takaisiin resolvereihin. IPv6 kokonaan kiinni.
  • Reititys kuten wg-quick: fwmark + oma taulu, klusterin verkot (RFC1918) pysyvät eth0:lla vain vastauksille.
  • Exit voi olla NATin takana: endpointiksi Tailscale-IP.

Exitit: yksi kontti millä tahansa koneella

  • hydra-exit: WireGuard-palvelin + NAT konttina, peer-pooli (oletus 8) volyymissä, MTU 1200 (Tailscale-polku 1280).
  • Ei pääsyä exitin lähiverkkoon: yksityiset verkot pudotetaan.
  • hydra exit add (Rust CLI): rakentaa imagen etäkoneen arkkitehtuurille, kopioi vain jos image-id muuttui, käynnistää, kirjoittaa peerit kube-Secreteiksi (server-side apply).
  • Näyttönimi annotaationa: --label "Kulloo, Finland", korvaa UI:ssa ipinfo.io:n kaupunkiarvauksen.
  • Kulloo: kone koti-/yritysliittymässä (Telia), NATin takana, Tailscalen kautta.
  • Cape Town: AWS af-south-1, t4g.micro (arm64), noin 12,4 $/kk hinnaston mukaan + liikenne.

Agentti: Claude Opus selaimen ohjaimena

  • Panelin oma silmukka: Messages API, claude-opus-5-5, adaptive thinking, MCP-työkalut suoraan podista.
  • Käyttäjän Claude-tilaus, ei API-avainta: hydra login kopioi tokenin Macilta Secretiin, launchd päivittää 10 min välein. Token ei tulostu.
  • "Aja kaikissa": sama tehtävä rinnakkain kaikissa selaimissa, askelloki ja vastaus lähteineen kortissa.
  • Ohje mallille: DuckDuckGo html tai Bing (ei Googlea), snapshotit kuvakaappausten sijaan, noin 25 askelta, vastaus suomeksi.
  • ask_human(reason): CAPTCHA, kirjautuminen tai maksu pysäyttää ajon, näkymä muuttuu ohjattavaksi, "Jatka" jatkaa.
  • Tilauksen raja (429) pysäyttää ajon, ei uudelleenyrityksiä.
